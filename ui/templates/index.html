RDMA transport (llama.cpp RPC)

Additional configs
Each config shares the same model file (Model ID / Path) but can have its own hardware, context, cache, and flags. They appear as separate entries on the Launch tab and as separate models in llama-swap. Existing single-config models are unchanged.

Model check

Downloads

Chat Test …

Chat with any configured model through llama-swap (the same OpenAI endpoint API clients use). Unloaded models load on first message — big ones take a while.

Embeddings Test …

Test embedding models (e.g. nomic-embed-text-v1.5.f16) via POST /v1/embeddings — not chat. Vectors stay in browser, cosine similarity computed locally.

First call may load the model (30-60s, up to 7200s on RAM).

How to configure

Scan for nomic-embed*.gguf → Configure → safe defaults will be ctx 8192 batch 512 parallel 1 (no jinja/draft-mtp). Set Group if needed, Save → Launch → Launch All. Then test here.

Vision Test …

Test vision models (mmproj configured) via POST /v1/chat/completions with an image. PNG/JPG only, sent as base64 from the browser — never stored.

First call may load the model (30-60s, up to 7200s on RAM).

How to configure

Model needs an mmproj flag (the projector file, e.g. mmproj-model-f16.gguf) — set it in Configure → Flags. Save → Launch → Launch All. Then test here.

Audio Test (Speech → Text) …

Test ASR models by speaking into your browser microphone. Click Start recording — the browser will prompt for microphone permission; recording only starts after you allow it (nothing is recorded or stored on the host). Clip goes to the model as base64 input_audio.

Browsers hide the mic on plain-http LAN pages by default. Firefox: about:config → media.devices.insecure.enabled AND media.getusermedia.insecure.enabled = true → fully quit and reopen Firefox (reload alone won't do it). Chrome/Edge: chrome://flags/#unsafely-treat-insecure-origin-as-secure → add this origin → relaunch. Zero-setup alternative: ssh -N -L 8199:10.0.0.104:8199 zazi@10.0.0.104 then open http://localhost:8199 (localhost is always trusted).

0.0s mic idle
First call may load the model (30-60s).

How to configure

Model id containing asr/whisper (or an audio flag) is listed here. Save → Launch → Launch All. Then test here.

Decision Test …

Test TypeSafe decision models (laya, kev, lev, openjev…) via POST /v1/systemone — sent straight to the llama-swap endpoint (:8080), which routes to the model named in the request. Send a state and typed questions — the model scores every option in one forward pass and returns probabilities (no text generation). Requires llama.cpp b11379+ and llama-swap v262+.

First call may load the model (30-60s, up to 7200s on RAM).

How to configure

Decision models are auto-detected from the GGUF's <arch>.decision.type metadata (laya → modern-bert). Scan → Configure → safe defaults set ctx 8192 ubatch 2048 (whole prompt evaluated in one batch), no jinja/sampling/MTP. Save → Launch → Launch All. Then test here.

Run together

                
Members run side by side, sharing VRAM. For small models that fit together.

              

              

                

                
Always-on

                
Members run side by side AND stay loaded — other loads can't auto-unload them.

              

              

                

                
Take turns

                
Big models that each need most of the cluster — loading one parks the others.

              

              

                

                
Take turns + always-on

                
Members take turns among themselves, but the group as a whole can't be auto-unloaded by outside loads.

              

              

                

                
Solo run

                
A model that clears the stage when it loads — unloads everything else, even outside this group.

              

              

                

                
Solo run + always-on

                
Clears the whole stage on load, and this group itself is immune to auto-unload.

           Engine
          

            
Serving engine for launches. llama.cpp serves GGUF via llama-server, spanning machines as an RPC cluster. vLLM is experimental — it serves HF models across machines via tensor/pipeline parallel over a Ray multi-node cluster (vLLM must be installed on each host). Works best on matched GPUs with fast interconnects; hybrid-architecture models (GDN/linear-attention) and mixed consumer GPUs may fail at engine init (upstream vLLM limitations). Panels on other tabs follow the engine; Save defaults to apply.

Access

        
      

      
Access by API KEY, not IP. A key's clients (Hermes, opencode, winbox, browsers) present Authorization: Bearer <key> and see ONLY the models granted to that key — chat, launch, swap, model pages, the :8090 gateway, everywhere. Each grant is exact: a model card = base entry, a variant card = that variant. Keys apply on the NEXT request after any change — no restart. Your browser adopts a key via the key box below.
